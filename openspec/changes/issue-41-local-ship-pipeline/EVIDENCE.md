An earlier reviewer round separately fixed the bounded terminal recovery bundle's
own correctness: the nested double filesystem failure inside `rollback()`'s

verifies the terminal recovery bundle's removal and returns a structured result;
`install`/`rollback`/`uninstall` all now surface a structured failure rather than
an unqualified success if that cleanup itself fails.

An earlier round implemented four further findings, all local-mechanism fixes with
no change to the hosted-CI acceptance status: (1) the triple-filesystem-failure
recovery narrowing planned in `design.md`/`spec.md` (tasks 6.1–6.4) was implemented
and proven with a self-cleaning-on-next-success treatment of the surviving path;
(2) Oracle fix #1: `uninstall()` now validates any existing rollback bundle before
deleting a valid active bundle, aborting without mutation if malformed; (3) Oracle
fix #2: the thin-`arm64` architecture assertion now runs at every lifecycle
eligibility boundary (static candidate, active, rollback, and transport validation,
via `validate_static_identity()`), strictly before any launch probe, not only
inside `build_candidate()`; the CI synthetic failed-update candidate now also
asserts `-arch arm64` explicitly; (4) Oracle fix #3: `_clear_pipeline_temp_state()`
now verifies removal of every pipeline-owned transient slot, not only the terminal
recovery bundle, and reports any leftover path as a structured cleanup failure.

**Terminal BLOCKED implementation (Issue #41 resolution comment 5658837706):** a
true triple filesystem failure leaves its bounded pipeline-owned survivor slot as
the sole BLOCKED signal; no `terminal-blocked.json` state exists. Cleanup never
sweeps a unique survivor; `install`, `rollback`, and `uninstall` refuse before
configuration capture, validation, or mutation and report that exact path. In the
nested post-rollback case, the outer validated backup remains the only reported
survivor; the generic helper's lower-value transient is removed without relocation.
If that removal fails, lifecycle fails closed without a unique-survivor claim.
Focused tests prove both triple-failure call sites, all-action refusal, nested
recovery, lower-value cleanup failure, and manual operator resolution. The bounded
terminal-recovery bundle for a double failure remains self-cleaning.
